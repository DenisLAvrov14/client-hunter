# Client Hunter

Находит традиционные бизнесы с конкретной проверяемой проблемой на сайте, готовит досье и персональное письмо. Оператор одобряет письма в Telegram. Полная спецификация: [docs/spec.md](docs/spec.md).

**Текущая фаза: поиск возможностей, этап C — глубокий анализ отобранных компаний и досье.** Этапы: A — поиск и проверка сайтов (без LLM), B — отбор через Claude Haiku (`npm run screen`), C — глубокий анализ и черновик первого письма для просмотра (`npm run deep`). Писем нет никаких: результат печатается в консоль и сохраняется в `data/reports/`. Отправка выключена (`SENDING_ENABLED=false`, `DRY_RUN=true`).

Что изменилось относительно спецификации — [docs/decisions.md](docs/decisions.md): юрлицо больше не фильтр, риск контакта хранится отдельно и на отбор не влияет, собирается и публичная почта (gmail и т. п.).

## Требования
- Node.js **24 LTS**
- Windows или Linux
- Ключи API для поиска и проверки сайтов **не нужны**. Для отбора и глубокого анализа через Claude (`npm run screen`, `npm run deep`) нужен `ANTHROPIC_API_KEY` в `.env` (отдельный платный API, не подписка Claude)

## Установка
```sh
npm install
npx playwright install chromium   # браузер для мобильных проверок и скриншотов
cp .env.example .env               # на Windows: copy .env.example .env
npm run check-config
```

## Запросы с намерением заказать разработку (основной поток)
```sh
npm run intent -- --dry-run   # собрать и разобрать, без записи в базу
npm run intent                # то же + сохранить в intent_leads (нужна миграция 007: резервная копия, затем npm run migrate)
npm run intent -- --secondary # добавить вторичные форумы (Bubble, n8n, Make)
```
Ищет **публичные запросы, где человек или компания сами хотят заказать готовую работу**.

**Источники:**
- **Основные — форумы владельцев бизнеса:** UK Business Forums, HigherLevel.nl и Shopify Community.
- **Дополнительно:** Hacker News («Seeking freelancer») и открытые IT-тендеры UK Contracts Finder.

Только публичные API и RSS-ленты, `robots.txt` соблюдается, ничего не отправляется.

**Разбор запросов:**
- **Что мы делаем** описывает профиль услуг [config/capabilities.yaml](config/capabilities.yaml): Shopify, full-stack, интеграции, i18n, миграции, платежи, фронтенд и техническое SEO, а также смежное и неподходящее.
- **Как читать запрос** задаёт [config/intent.yaml](config/intent.yaml).
- **Категория покупателя:** прямой заказчик, просьба порекомендовать исполнителя, возможный заказчик, агентство-субподряд, найм, исполнитель, нерелевантно.
- **Совпадение с профилем:** CORE, ADJACENT, CONDITIONAL или POOR.
- **LLM** не используется. С флагом `--llm` Haiku проверяет только неоднозначные запросы, в пределах `--max-llm-usd`.

**Отчёт** — `data/reports/intent-*.md` и `.csv`:
- **Воронка:** сколько источников просмотрено, сколько явных запросов покупателей, сколько из них CORE и сколько готово к ответу.
- **Пять разделов:** прямые заказчики, рекомендации, возможные заказчики, агентства, отклонённые.
- **По каждому запросу:** ссылка на оригинал, дата, честный статус (OPEN, CLOSED или UNKNOWN), цитата намерения, можно ли работать удалённо, канал ответа, причины решения и чего не хватает.

Ссылки из прошлых отчётов помечаются как «уже были».

Сканер сайтов ниже остаётся вспомогательным инструментом и в этот отчёт не попадает.

## Как посмотреть поиск
```sh
npm run pipeline -- --market UK --segment S2 --limit 10
```
Что происходит:
1. **Поиск** — OpenStreetMap (Overpass) по городам из `discovery_cities` в `config/markets/uk.yaml` и тегам сегмента. Найденные компании сохраняются в базу (дубли по домену склеиваются).
2. **Проверка** — по `--limit` случайных необработанных компаний: robots.txt → главная → до 5 важных страниц → тип юрлица по тексту сайта → проверки из раздела 8.3 спеки → мобильная проверка в Chromium (390×844, скриншоты) → контакты с MX-проверкой.
3. **Вывод** — строка в консоль на каждую компанию, итог, и отчёт `data/reports/candidates-UK-*.md` + `.csv`.

Полезные флаги:
- `--no-discovery` — не искать заново, проверить ещё необработанные компании из базы
- `--no-browser` — без Chromium (быстрее, без скриншотов и мобильных проверок)
- `--segment S1` — Shopify-магазины (всё, что не Shopify, отсеивается)

Публичный Overpass иногда перегружен (HTTP 502/504) — программа сама ждёт и повторяет до 4 раз, а если город так и не ответил, переходит к следующему.

## Глубокий анализ (этап C)
```sh
npm run deep -- --dry-run --domain a1designs.co.uk --domain freza.ru   # что уйдёт в Claude и сколько стоит, без API
npm run deep -- --domain a1designs.co.uk --domain freza.ru             # платно
```
Для каждой компании из базы (нужна успешная проверка сайта):
1. Claude Haiku получает очищенный текст сайта, находки проверок, признаки уже имеющихся возможностей и список внутренних ссылок. Текст сайта — данные, не инструкции.
2. Модель может попросить прочитать до 3 страниц из известных ссылок сайта; код читает их сам (robots.txt, лимиты размера) и сохраняет как отдельную проверку `deep_pages`, не меняя данных основной проверки.
3. Код проверяет ответ: цитата должна быть в тексте страницы, находка — в базе, признак сайта — определён кодом (по ключу, например `cart_checkout`). Иначе утверждение понижается: факт → вывод → гипотеза. Предложение того, что на сайте уже есть, не считается. «Стоит предложить» — только если лучшее предложение опирается хотя бы на один факт; неизвестные объёмы заказов этому не мешают.
4. Черновик письма проверяется правилами `config/copy-rules.yaml` и опорой на доказательства: он должен быть о выбранном предложении и опираться на одно его наблюдение. Факт можно назвать, о выводе — только спросить, на гипотезе письмо строить нельзя. Строку отказа добавляет код. Черновик, не прошедший проверку, помечается как непригодный.
5. Досье — `data/reports/dossiers-*.md`: о бизнесе, как клиент взаимодействует сейчас, лучшее предложение и другие варианты (каждое утверждение помечено ✅ факт / 🔹 вывод / 💭 гипотеза / ❓ неизвестно), контакты и **отдельно** риск обращения, черновик письма **только для просмотра**.
6. Контакты — сначала email: публичный адрес на сайте (на домене компании или gmail и т. п.) с источником и риском адреса. Без email — пометка «нужен ручной поиск контакта» (форма — запасной канал, её заполняет человек; адрес, скрытый защитой от сбора, код не расшифровывает).

Стоимость: до 4 вызовов анализа на компанию (2 прохода по 2 попытки) и не больше одного небольшого вызова ремонта письма: если анализ верен, а не прошло только письмо, заново генерируется только письмо, а не всё досье (стоимость анализа и ремонта показывается отдельно). Лимиты на запуск и месяц — `config/limits.yaml`; запуск останавливается до вызова, который мог бы их превысить. Скрытых повторов нет: SDK сам не повторяет запросы, каждая попытка учитывается в бюджете. Обрезанный по лимиту токенов ответ повторяется один раз с другими настройками (`on_truncation` в `config/llm.yaml`) и просьбой отвечать короче, а не тем же запросом. Повторный запуск с теми же данными сайта берётся из кэша бесплатно (`--force` — анализировать заново, платно).

`--dry-run` только читает базу: не применяет миграции и не вызывает API. Если в базе не применены миграции, он попросит сначала сделать резервную копию и выполнить `npm run migrate`. Обычный запуск применяет миграции сам, как остальные команды.

## Команды
| Команда | Что делает |
|---|---|
| `npm run pipeline -- --market UK --segment S2 --limit 10` | поиск + проверка + отчёт |
| `npm run report:candidates -- --market UK` | пересобрать отчёт из базы |
| `npm run reinspect -- --dry-run` | сколько компаний, отсеянных по старым правилам, будет перепроверено |
| `npm run reinspect -- --market UK --limit 50` | перепроверить их по новым правилам (без браузера; `--browser` — с мобильными проверками) |
| `npm run reinspect -- --browser --domain a.co.uk --domain b.kz` | перепроверить именно эти компании текущим кодом (например, короткий список перед этапом C; бесплатно, без LLM) |
| `npm run screen -- --dry-run --domain example.co.uk` | показать, что уйдёт в Claude Haiku, и оценку стоимости — **без вызова API** |
| `npm run screen -- --market UK --limit 10` | этап B: отбор компаний через Claude Haiku (**платно**, ~$0.001 за компанию; лимиты в `config/limits.yaml`) |
| `npm run deep -- --dry-run --domain example.co.uk` | этап C: показать вход и оценку стоимости — **без вызова API и без записи в базу** |
| `npm run deep -- --domain example.co.uk [--domain …]` | этап C: глубокий анализ и досье с черновиком письма для просмотра (**платно**; ничего не отправляется) |
| `npm run leads` | коммерческие лиды по сохранённым данным (без LLM): проекты, которые можно продать, а не дефекты сайта; `data/reports/leads-*.md` и `.csv` |
| `npm run import-csv -- --file list.csv --market UK --segment S2` | добавить свои домены (CSV: `website,name,city` или по домену в строке) |
| `npm run migrate` | применить `migrations/*.sql` |
| `npm run check-config` | проверить `config/` и флаги из `.env` |
| `npm test` · `npm run typecheck` · `npm run lint` | тесты (без сети и почты), типы, линтер |

## Что пока упрощено (без регистраций)
- **Companies House не подключён** — тип юрлица (Ltd/Limited/PLC/LLP и номер компании) берётся с сайта, `registry_status = not_checked`. Для Фазы 4 нужен бесплатный ключ.
- **PageSpeed не подключён** — проверки `SLOW_MOBILE` нет.
- **User-Agent** бота ссылается на этот репозиторий; заменить на страницу о боте на своём домене, когда он появится (`config/app.yaml`).

## Причины автоотказа (`reject_reason`)
| Код | Значение |
|---|---|
| `site_unreachable`, `home_http_NNN`, `home_not_html` | сайт не открылся |
| `robots_disallow`, `robots_unavailable` | robots.txt запрещает нам заходить |
| `redirects_offsite` | сайт перенаправляет на другой домен |
| `parked_domain` | домен припаркован / продаётся |
| `not_shopify`, `store_closed`, `too_few_products` | для S1 |
| `suppressed` | домен в suppression list |

Больше **не** отсеивают (с 2026-10-23): неизвестное юрлицо, ИП, отсутствие email, отсутствие технических проблем. Это записывается в базу, а законность холодного письма — отдельное поле «риск контакта» (`low` / `review_required` / `high`) рядом с компанией в отчёте.

## Конфиги
| Файл | Что внутри |
|---|---|
| `config/app.yaml` | часовой пояс оператора, User-Agent, порог score |
| `config/limits.yaml` | лимиты: страниц на сайт, задержки, таймауты, параллельность |
| `config/llm.yaml` | модели, лимиты ответа и цены токенов для этапов B (`screen`) и C (`deep`) |
| `config/scoring.yaml` | веса скоринга (Фаза 2, не откалиброваны) |
| `config/offers.yaml` | офферы O1–O3 и цены-гипотезы |
| `config/copy-rules.yaml` | правила текста писем (Фаза 2) |
| `config/markets/*.yaml` | юридические профили рынков; включён только UK |
| `config/segments/*.yaml` | OSM-теги, SIC-коды по сегментам |
