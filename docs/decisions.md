# Решения, меняющие спецификацию v3

Спецификация: [spec.md](spec.md). Здесь — решения оператора, принятые после неё. При расхождении действует этот файл.

---

## 2026-10-23 — Поиск возможностей вместо поиска дефектов

**Решение оператора** (план «Client Hunter — Updated Development Plan», одобрен 2026-10-23).

### 1. Юрлицо больше не фильтр
- Раньше (спека 3.1, 5.4, 8.6): сайт без признаков юрлица или с признаками ИП → `rejected_auto` (`entity_unknown`, `entity_sole_trader`).
- Теперь: тип юрлица определяется и сохраняется, но **никого не отсеивает**. Анализируются все коммерческие сайты: компании, ИП, независимые специалисты.
- Также больше не отсеивают: `no_verified_observation` (категория B не требует дефектов), `no_contact`, `no_mx`.
- Отсеиваются только сайты, анализ которых невозможен: недоступен, robots.txt, припаркован, редирект на чужой домен, дубликат. Плюс правила сегмента S1 (не Shopify, магазин закрыт).

### 2. Риск контакта — отдельное поле (`outreach_risk`)
- Коммерческая ценность компании и законность холодного письма — **разные вопросы**. Риск хранится отдельно (таблица `outreach_risk`), показывается рядом с компанией и **никогда не влияет на отбор и ранжирование**.
- Классы: `low` / `review_required` / `high`; с причиной, уверенностью, неизвестными и тем, что проверить до контакта.
- Правила — код ([src/outreach/risk.ts](../src/outreach/risk.ts)) + `cold_email_baseline` в профиле рынка. Это рабочая конфигурация, не юридическая консультация.
- `low` не означает гарантированного разрешения. Одобрение оператора не отменяет требований закона.
- Автоматической отправки нет.

### 3. Контакты
- Собираются все публично указанные на сайте адреса: на домене компании **и публичная почта** (gmail, outlook, ISP). Раньше публичная почта отбрасывалась (`allow_freemail_addresses: false`).
- Публичная почта никогда не даёт `low`: это часто личный ящик (персональные данные по GDPR).
- По-прежнему не собираются служебные адреса: noreply, privacy, dpo, jobs/careers/hr, accounts/invoices, webmaster/postmaster/abuse.
- Поля профиля рынка `allow_freemail_addresses`, `allow_named_business_address` теперь влияют только на риск, не на сбор.

### 4. Ограниченная инспекция
- До 6 страниц на сайт; приоритет: главная, о компании, услуги, каталог, контакты, сценарий клиента (заявка/бронь/заказ/цены); юридические — только на оставшиеся места. Статьи блога и новостей не открываются.
- Сохраняется очищенный основной текст страницы (без меню/футера/баннеров, строки, повторяющиеся на разных страницах сайта, убираются) — до `page_main_text_max_chars` — и до `page_links_max` внутренних ссылок.
- Признаки уже имеющихся возможностей сайта (корзина, форма, онлайн-бронь, калькулятор, поиск, цены, личный кабинет, чат, мессенджеры) считаются кодом.
- Каждая проверка — запись в `inspections`; старые страницы и находки не перезаписываются.

### 5. LLM
- Используется **Claude Haiku** (через API, отдельный биллинг) и для отбора, и для глубокого анализа — вместо Sonnet для досье (спека 9.1). Модель меняется в `config/llm.yaml`.

### 6. Сегмент S3
- Новый сегмент: локальные услуги и независимые специалисты (фотографы, салоны, мастерские, школы, архитекторы, консультанты) — [config/segments/s3-local-services.yaml](../config/segments/s3-local-services.yaml).
