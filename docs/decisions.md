# Решения, меняющие спецификацию v3

Спецификация: [spec.md](spec.md). Здесь — решения оператора, принятые после неё. При расхождении действует этот файл.

## 2026-10-23 — Поиск возможностей вместо поиска дефектов

**Решение оператора** (план «Client Hunter — Updated Development Plan», одобрен 2026-10-23).

### 1. Юрлицо больше не фильтр
- Раньше (спека 3.1, 5.4, 8.6): сайт без признаков юрлица или с признаками ИП → `rejected_auto` (`entity_unknown`, `entity_sole_trader`).
- Теперь: тип юрлица определяется и сохраняется, но **никого не отсеивает**. Анализируются все коммерческие сайты: компании, ИП, независимые специалисты.
- Также больше не отсеивают: `no_verified_observation` (категория B не требует дефектов), `no_contact`, `no_mx`.
- Отсеиваются только сайты, анализ которых невозможен: недоступен, robots.txt, припаркован, редирект на чужой домен, дубликат. Плюс правила сегмента S1 (не Shopify, магазин закрыт).

### 2. Риск контакта — отдельное поле (`outreach_risk`)
- Коммерческая ценность компании и законность холодного письма — **разные вопросы**. Риск хранится отдельно (таблица `outreach_risk`), показывается рядом с компанией и **никогда не влияет на отбор и ранжирование**.
- Классы: `low` / `review_required` / `high`; с причиной, уверенностью, неизвестными и тем, что проверить до контакта.
- Правила — код ([src/outreach/risk.ts](../src/outreach/risk.ts)) + `cold_email_baseline` в профиле рынка. Это рабочая конфигурация, не юридическая консультация.
- `low` не означает гарантированного разрешения. Одобрение оператора не отменяет требований закона.
- Риск определяется правилами рынка и типом получателя, **не наличием email** (правила `2026-10-23.2`). Доступность контакта — отдельное поле `contact_status`: `email` / `form_only` / `phone_or_messenger` / `none`. Для отдельного адреса риск может быть выше, чем для получателя (публичная почта, именной адрес).
- Автоматической отправки нет.

### 3. Контакты
- Собираются все публично указанные на сайте адреса: на домене компании **и публичная почта** (gmail, outlook, ISP). Раньше публичная почта отбрасывалась (`allow_freemail_addresses: false`).
- Публичная почта никогда не даёт `low`: это часто личный ящик (персональные данные по GDPR).
- По-прежнему не собираются служебные адреса: noreply, privacy, dpo, jobs/careers/hr, accounts/invoices, webmaster/postmaster/abuse.
- Поля профиля рынка `allow_freemail_addresses`, `allow_named_business_address` теперь влияют только на риск, не на сбор.
- Кроме email сохраняются другие публичные каналы (таблица `contact_channels`): страница с контактной формой, телефон (ссылки `tel:` и подписанные номера на странице контактов, в шапке и футере), WhatsApp и Telegram (ссылки на чат, не кнопки «поделиться»). Номера из комментариев, отзывов и цитат не собираются. Ничего не отправляется и не заполняется.

### 4. Ограниченная инспекция
- До 6 страниц на сайт; приоритет: главная, о компании, услуги, каталог, контакты, сценарий клиента (заявка/бронь/заказ/цены); юридические — только на оставшиеся места. Статьи блога и новостей не открываются.
- Сохраняется очищенный основной текст страницы (без меню/футера/баннеров, строки, повторяющиеся на разных страницах сайта, убираются) — до `page_main_text_max_chars` — и до `page_links_max` внутренних ссылок.
- Признаки уже имеющихся возможностей сайта (корзина, форма, онлайн-бронь, калькулятор, поиск, цены, личный кабинет, чат, мессенджеры) считаются кодом.
- Каждая проверка — запись в `inspections`; старые страницы и находки не перезаписываются.

### 5. LLM
- Используется **Claude Haiku** (через API, отдельный биллинг) и для отбора, и для глубокого анализа — вместо Sonnet для досье (спека 9.1). Модель меняется в `config/llm.yaml`.

### 6. Сегмент S3
- Новый сегмент: локальные услуги и независимые специалисты (фотографы, салоны, мастерские, школы, архитекторы, консультанты) — [config/segments/s3-local-services.yaml](../config/segments/s3-local-services.yaml).

## 2026-10-24 — Этап C: глубокий анализ и досье

Архитектурные решения Claude Code в рамках плана от 2026-10-23 (задача [#1](https://github.com/DenisLAvrov14/client-hunter/issues/1)); оператор принимает их при ревью PR.

### 1. Что делает этап C
- `npm run deep -- --domain …` — только для явно указанных компаний (короткий список после этапа B), не массово.
- Claude Haiku (`config/llm.yaml`, `stages.deep`) получает тот же очищенный текст сайта, что и этап B, но с большим лимитом, плюс известные внутренние ссылки и доступность контакта.
- Модель может запросить до 3 страниц только из известных внутренних ссылок; код читает их сам с учётом robots.txt и сохраняет как отдельную проверку (`inspections.mode = 'deep_pages'`, `result_status = 'supplement'`). Логика контактов по-прежнему опирается только на последнюю настоящую проверку.

### 2. Доказательства проверяет код, не модель
- Каждое утверждение — `fact` / `inference` / `hypothesis` / `unknown` со ссылками на доказательства: цитата со страницы, находка из `observations`, признак сайта, определённый кодом.
- Цитаты ищутся в тексте страниц, находки — в базе. Непроверяемое доказательство удаляется, утверждение понижается (факт → вывод → гипотеза). Находка `likely` подтверждает только вывод, не факт.
- Цитата должна быть на той странице, которую указала модель (адреса сравниваются без завершающего `/` и `#якоря`). Если цитата найдена на другой странице сайта, адрес исправляется на настоящий, она подтверждает только вывод, не факт, и модель получает просьбу указать верную страницу. Неверный адрес в досье не попадает. То же для этапа B: адрес цитаты исправляется на настоящий.
- Предложение того, что на сайте уже есть, не засчитывается; `pursue` без обоснованного предложения становится `maybe`.

### 3. Черновик письма — только для просмотра
- Черновик проверяется правилами `config/copy-rules.yaml` (язык, режим рынка, без цифр и чужих ссылок, длина, запрещённые фразы). Строку отказа добавляет код, не модель.
- Не прошедший проверку черновик помечается в досье как непригодный. Ничего не отправляется: этап C не обращается к почте.
- В досье риск обращения (`outreach_risk`) показан отдельно от доступности контакта (`contact_status`) и на рекомендацию не влияет.

### 4. Стоимость
- До 4 вызовов на компанию (2 прохода × 2 попытки). Перед каждым вызовом проверяется худший случай против лимитов на запуск и месяц (`config/limits.yaml`).
- Автоматические повторы SDK Anthropic отключены (`maxRetries: 0`, по умолчанию SDK повторяет до 2 раз): один вызов — ровно один HTTP-запрос, и каждый проходит проверку и учёт бюджета. Временные ошибки (429, 5xx, сеть) повторяют сами этапы B и C, каждая попытка учитывается; если API не сообщил расход, записывается худший случай. Параметр `sdk_max_retries` удалён из `config/llm.yaml`.
- Результат кэшируется по хэшу (модель + версия промпта + вход): повторный запуск с теми же данными бесплатен; изменённый промпт получает новую версию автоматически.
- `--dry-run` открывает базу только для чтения: не применяет миграции, не пишет, не вызывает API. Показывает вход первой компании, сколько компаний будет проанализировано и сколько взято из кэша, и оценку: обычную и худшую.

### 5. Доступ к данным
- Риск получателя, риск адресов, доступность контакта и находки читаются через функции `src/db/repo.ts`, одинаково для отчёта кандидатов, отчёта отбора и досье.
- Строки риска по старым правилам `2026-10-23.1` (там строка без контакта означала «email не найден») не показываются как риск получателя; версия хранится в одной константе рядом с `RISK_RULES_VERSION`.
